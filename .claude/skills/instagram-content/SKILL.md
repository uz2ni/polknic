# 폴크닉 인스타 콘텐츠

명령어·파일 구조는 [marketing/instagram/README.md](../../../marketing/instagram/README.md). 이 문서는 순서와 판단 기준만 적는다.
계정 `@yujamong.pole`은 사용자의 폴 서비스 공용 계정이다. 프로필은 폴크닉 전용으로 바꾸지 않고, 게시물 첫 줄에 "폴크닉"을 넣는다.

## 0. 언제 제안하나

- **기능을 끝냈을 때**: 플레이어가 화면에서 볼 수 있는 기능(새 동작·소품·장소·UI·이벤트)을 끝낸 대화에서는 마무리할 때 인스타 콘텐츠를 만들지 묻는다. 소재 한 줄 + 형식(릴스/카드뉴스/둘 다)과 이유를 함께. 사용자가 좋다고 하면 그 대화에서 바로 만든다. 버그 수정·내부 개선·성능처럼 보여 줄 게 없으면 묻지 않는다
- **정기 제안**(예약 작업이 이 스킬로 실행될 때): 만들지 말고 제안만 한다
  1. 지난 제안 뒤로 `main`에 들어간 커밋(`git log`), CLAUDE.md "플레이어 기능", `posts.html` section id·`reels/`를 보고 아직 안 다룬 소재를 찾는다
  2. 기능이 아니어도 된다: 시간대·계절(밤 하늘, 노을 BGM, 연말), 플레이 팁, 옷 조합, 폴메이트 모으기, 게시판 기술 요청 소개, 공지 등
  3. 2~3개를 제안: 소재 · 형식과 이유 · 첫 제목(질문형) · 올릴 날짜. 최근 게시물 형식과 겹치지 않게
  4. 파일을 고치거나 렌더·커밋하지 않는다. 사용자가 고르면 그때 만든다

## 1. 기획

- 소재는 실제 게임 기능에서만 고른다. 기능·수치(인원, 동작 이름, 방 개수)는 기억으로 쓰지 말고 CLAUDE.md "플레이어 기능"과 코드에서 확인한다
- 이미 다룬 것은 `posts.html`의 section id와 `reels/`를 보고 겹치지 않게 한다
- 형식 고르기: 사용자가 정하지 않았으면 묻지 말고 직접 판단해 이유를 한 줄로 알린다. 둘 다 쓰면 좋은 소재는 릴스와 카드뉴스를 모두 만들고 올릴 시점까지 제안한다(최근 게시물 형식과 예정된 일정을 보고 날짜나 간격으로)
  - 카드뉴스(1080×1440): 설명이 필요한 것. 표지 + 안쪽 장
  - 릴스(1080×1920): 움직임이 핵심인 것(같이 타기, 회전, 스트레칭 동작)
  - 스토리: 짧은 공지, 링크 스티커로 유입
- 시리즈 색: 소식 `news` 핑크 · 폴 기술 도감 `move` 하늘 · 폴메이트 `mate` 버터 · 옷장 `closet` 라일락 · 폴짝 매점 `shop` 복숭아 · 폴크닉 꿀팁 `tip` 민트(posts.html 안에 정의)
- 디자인이 비슷해 보이지 않게 한다. 사진 위 큰 제목만 반복하지 말고, 색 바탕 + 카드 격자(`p02-moves`)나 소재에 맞는 모양(매점의 줄무늬 차양·메뉴판)을 고른다
- 소재가 같은 릴스와 카드뉴스를 둘 다 올릴 땐 내용을 나눈다(릴스는 움직임과 재미, 카드뉴스는 정보). 기본 시점은 릴스를 먼저, 3~7일 뒤에 카드뉴스
- 이미지·영상 소재는 게임 렌더만 쓴다. 외부 이미지·폰트·음원은 넣지 않는다(소리는 사용자가 인스타 앱에서 얹는다)

## 2. 만들기

- 카드뉴스: `shots.json`에 렌더 추가(`__poleDebug` 훅이나 `scenes/` 스크립트) → `posts.html`에 section 추가 → `npm run build`
- 릴스: `reels/tanghulu.js`를 틀로 `reels/<이름>.js` 작성
  - 장면은 `scene`의 `frame(t)`에서 `x.update(dt)` → 카메라 직접 배치 → `render`. 게임 카메라에 맡기지 않는다
  - 카메라는 화면에 넣을 대상의 높이 범위에서 거리를 계산한다(탕후루의 `cam()`처럼). 고정 숫자로 잡으면 사람이 늘 때 제목과 겹친다
  - 글자는 `data-in`/`data-out`(초). 한 장면 1.5~2초, 전체 10~15초. 첫 2초에 질문형 제목
  - 끝 장면: 입장 안내 패널(글자 로고 + 한 줄 + "프로필 링크에서 바로 입장" + 버튼). 카메라가 다 움직인 뒤에 패널이 뜨게
  - 릴스에 뜨는 박스(메뉴·입장 안내 패널)는 모두 같은 자리: 가운데, 조금 아래(`left:150px;right:150px;bottom:340px`, `reels/shop.js`). 아래 400px 규칙의 예외. 한 박스를 옮기면 같은 릴스의 다른 박스도 함께 옮긴다
- 배치 규칙
  - 릴스 글자는 위 210px·아래 400px·오른쪽 150px 안쪽(`reels/reel.css`). 박스는 위 예외를 따른다
  - 그리드에 보이는 영역: 카드뉴스는 1:1(위아래 180px 안), 릴스 표지는 가운데 3:4(위아래 240px 안)

## 3. 확인 (렌더해서 눈으로)

1. 스틸 몇 장 먼저: `npm run reel -- <이름> 1 3.5 8 …` 결과를 한 장으로 모아 보고 겹침·잘림·너무 작은 캐릭터 확인
2. 고친 뒤 전체 렌더 `npm run reel -- <이름>` (ffmpeg 필요)
3. 장면이 바뀌는 순간 프레임(`reels/frames/<이름>/`)을 다시 본다. 전환 중 겹침은 스틸에선 안 보인다
4. 테스트용 스틸 PNG는 지우고, 결과 mp4·PNG는 사용자에게 파일로 보낸다

## 4. 표지

- 릴스 파일의 `cover`(at, html, css, opts)로 따로 만든다. 영상 프레임을 그대로 쓰지 않는다
- 각도 비교: `npm run reel -- <이름> cover -0.8 0 0.8 1.6 2.4` → 얼굴이 많이 보이고 배경이 깔끔한 각도를 `opts.yaw`로
- 가운데 3:4로 잘라 그리드에서 어떻게 보이는지 확인
- 문구는 영상 첫 제목과 맞춘다. 낚시성 문구는 쓰지 않는다
- 표지에 기능 세부 설명을 덧붙이지 않는다(예: "워터마크까지 찰칵"은 필요 없는 말이었음). 없어도 되는 칩은 뺀다

## 문구·표현

- 가격을 내세우지 않는다: "무료", "0원", 합계·가격표를 게시물·캡션에 쓰지 않는다. 광고나 포인트 구매를 붙일 계획이고 게시물은 피드에 계속 남기 때문. 꼭 알려야 하면 24시간 뒤 사라지는 스토리에서만
- 메뉴·목록 카드는 항목 이름 왼쪽에 이모지를 넣는다. 게임에 정해진 아이콘이 있으면 그것(매점은 `SNACKS`의 `icon`)을 쓴다

## 5. 업로드 문구

- 캡션: 첫 줄 `[폴크닉] 질문이나 한 줄 요약` → 기능 설명 → 하는 법(번호) → "프로필 링크에서 입장"
- 캡션 이모지(사용자가 실제로 올린 말투, 2026-11-12 앱처럼 쓰기 카드뉴스):
  - 거의 모든 문장 끝에 이모지 하나(마침표 뒤에 붙여도 됨): 질문엔 🙋🏻‍♀️, 놀람·자랑엔 🫢, 가볍게 ✌🏻
  - 사람·손 이모지는 밝은 피부톤 🏻, 사람은 여성형 ♀️(🙋🏻‍♀️ 🙅🏻‍♀️ 🙆🏻‍♀️ 👉🏻)
  - 주의·하지 말 것은 🙅🏻‍♀️, 이렇게 하면 된다는 해결은 🙆🏻‍♀️로 짝지음
  - 묶음 제목 앞에 기기·주제 이모지(📱 아이폰, 🤖 안드로이드), 번호 목록 줄엔 이모지 없음
  - 마지막 줄 `프로필 링크에서 입장 👉🏻 @yujamong.pole`
  - 버튼·메뉴 이름은 ‘ ’ 따옴표
- 예시(실제 게시 문구):
  ```
  [폴크닉] 매번 주소 찾아 들어오기 귀찮았던 폴메이트? 🙋🏻‍♀️

  홈 화면에 아이콘 하나 만들어 두면 앱처럼 톡 누르고 바로 호숫가로 갈 수 있어요 🫢
  설치 파일도 가입도 필요 없어요.✌🏻

  📱 아이폰
  1. 프로필 링크를 Safari로 열기
  2. 공유 버튼 → 홈 화면에 추가
  3. 오른쪽 위 ’추가‘

  인스타 안에서 열면 메뉴가 안 보여요! 🙅🏻‍♀️
  오른쪽 위 점 세 개 → 외부 브라우저로 열기를 먼저 해 주세요. 🙆🏻‍♀️

  프로필 링크에서 입장 👉🏻 @yujamong.pole

  #폴크닉 #폴댄스 #폴스타그램 #웹게임 #꿀팁
  ```
- 해시태그는 **최대 5개**(인스타 제한). 기본 `#폴크닉 #폴댄스 #폴린이 #폴스타그램 #웹게임`, 소재에 맞게 1~2개 교체
- 고정 댓글: 친구를 @태그하게 하는 한 줄. 해시태그는 넣지 않는다
- 업로드 설정표: 커버(카메라 롤에서 추가), 프로필 그리드 표시, 음원 분위기, 대체 텍스트
- 스토리 링크 스티커는 UTM 링크([docs/marketing/utm-guide.md](../../../docs/marketing/utm-guide.md)). 가이드에 없는 조합이면 표와 변경 이력에 추가
- 효과 확인용으로 그 기능의 GA4 이벤트를 알려 준다([docs/analytics.md](../../../docs/analytics.md))

## 하지 않을 것

- 인스타에 직접 올리기, 계정 설정 바꾸기(사용자가 한다)
- 묻지 않고 커밋·푸시
- `npm run export`로 전체 내보내기(바꾸지 않은 게시물 PNG까지 다시 써짐). `node scripts/export.js <id>`로 고친 장만
