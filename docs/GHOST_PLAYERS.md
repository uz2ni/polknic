# 유령 캐릭터 정리 (2026-11-06)

앱을 제대로 닫지 않고 나간 사람의 캐릭터가 방에 계속 남아 있던 문제와, 그걸 고친 과정.

## 증상

- 폰에서 폴크닉을 보다가 홈으로 나가거나, 다른 앱으로 넘어가거나, 화면을 꺼 버리면 그 사람 캐릭터가 다른 사람 화면에 그대로 서 있음
- 그 사람이 잡고 있던 폴·매트·같이 타기도 풀리지 않아 다른 사람이 못 씀
- 탭을 닫거나 새로고침한 경우는 바로 사라짐(정상)

## 원인

서버(방 = Durable Object)는 **"연결이 끊겼다"는 신호(`webSocketClose`)로만** 누가 나갔는지 안다.

1. 폰에서 앱을 내리거나 화면이 꺼지면 브라우저는 페이지를 **멈출 뿐 웹소켓을 닫지 않는 경우가 많다.** TCP 연결이 살아 있는 것처럼 남아서 Cloudflare도 한동안 끊긴 줄 모른다.
2. 게임은 25초마다 `ping`을 보내 연결을 확인한다. 그런데 요금을 아끼려고 `ping` → `pong`은 **Cloudflare가 방을 깨우지 않고 대신 답하게** 해 두었다(`setWebSocketAutoResponse`). 그래서 방 코드는 ping이 오는지 안 오는지 볼 일이 없었다.
3. 결과적으로 멈춘 페이지는 아무것도 안 보내는데, 방은 그걸 알아챌 방법이 없어서 캐릭터를 계속 보여 준다.

데스크톱에서도 같은 일이 있을 수 있다. 숨겨진 탭은 화면 갱신 루프(requestAnimationFrame)가 멈춰서 ping도 멈추지만, 소켓은 열려 있다.

## 해결

### 1. 서버: 오래 조용한 접속 내보내기 ([server/src/index.js](../server/src/index.js) `alarm()`)

- 방에 소켓이 하나라도 있으면 **Durable Object 알람**을 걸어 30초마다 접속을 훑는다
- 접속마다 "마지막 소식" = 마지막 메시지 시각(`attachment.seen`, 메시지를 받을 때마다 갱신)과 마지막 ping 시각(`ctx.getWebSocketAutoResponseTimestamp(ws)`, Cloudflare가 대신 답한 시각) 중 늦은 쪽
- 마지막 소식이 **60초**(`IDLE_SEC`)보다 오래됐으면
  - `leave()`: 다른 사람들에게 `leave`를 보내고 폴·매트·같이 타기를 푼다(정상 퇴장과 같은 처리)
  - attachment에 `gone: true`를 남기고 `close(4003, 'idle')`
- `gone` 소켓은 정원 계산과 다음 훑기에서 뺀다(죽은 연결은 닫는 중 상태로 한동안 남을 수 있어서)
- 소켓이 하나도 안 남으면 알람을 다시 걸지 않는다 → 빈 방은 깨우지 않음

왜 이렇게 했나:
- **ping 자동 응답은 그대로 유지**: ping마다 방을 깨우면 20명 × 25초마다라 요금이 오른다. 대신 Cloudflare가 기록해 둔 자동 응답 시각을 알람 때만 읽는다
- **60초**: 화면이 켜진 사람은 25초마다 ping을 보내므로 60초 안에 최소 두 번 소식이 온다. 잠깐 다른 앱을 보고 오는 정도로는 안 쫓겨나게 1분을 줬다
- **30초 간격**: 늦어도 1분 30초 안에 정리된다. 알람은 사람이 있는 방만 깨우므로 비용이 작다

### 2. 게임: 페이지를 떠날 때 바로 끊기, 숨겨진 동안은 재접속 안 하기 ([index.html](../index.html) 멀티플레이 블록)

- `pagehide`(탭 닫기, 다른 페이지로 이동, 뒤로 가기 캐시에 들어감)에서 소켓을 바로 닫는다 → 서버의 1분을 안 기다리고 즉시 사라짐. 캐시에서 돌아오면(`pageshow`의 `persisted`) 다시 입장
- **숨겨진 페이지는 재접속하지 않는다**(`netRetry`, `netNow`에 `document.hidden` 검사). 이게 없으면 서버가 내보낸 숨은 탭이 바로 다시 들어와 또 1분짜리 유령이 되는 걸 반복한다. 페이지로 돌아오면 `visibilitychange`에서 바로 다시 들어온다
- 끊길 때 정리하던 코드를 `netReset()`으로 묶어 `netClosed`와 `pagehide`가 같이 씀

## 사용자 입장에서 바뀐 점

- 앱을 내리고 1분쯤 지나면 다른 사람 화면에서 내 캐릭터가 사라지고 채팅 기록에 "○○님이 나갔어요"가 뜬다
- 다시 앱으로 돌아오면 자동으로 다시 들어온다. 하던 폴 동작·같이 타기·매트는 풀린 상태(혼자서는 계속 그 자리에서 놀 수 있음)

## 확인한 방법

- 서버 단독: [server/test/idle.mjs](../server/test/idle.mjs). 정리 시간을 4초로 줄여 띄우고 실행
  ```bash
  cd server && npx wrangler dev --port 8790 --var IDLE_SEC:4
  ```
  ```bash
  cd server && WS_URL=ws://127.0.0.1:8790 npm run test:idle
  ```
  조용한 사람은 나감 알림 + 폴 풀림 + 4003으로 닫힘, ping만 보내는 사람은 남음, 나갔던 사람은 다시 정상 입장
- 기존 [server/test/smoke.mjs](../server/test/smoke.mjs)도 그대로 통과(기본 60초라 영향 없음)
- 브라우저 두 탭(로컬 서버 `IDLE_SEC:4`):
  - 숨은 탭(`document.hidden`을 true로 흉내): 몇 초 뒤 다른 탭에서 사라지고, 13초 넘게 다시 안 나타남. 숨김을 풀면 바로 다시 입장
  - 탭 닫기: 다른 탭에서 바로 사라짐

## 남은 점·주의

- 입장(join) 전에 아무것도 안 보내는 소켓도 같은 훑기에서 정원·목록에서 빠지고 `close(4003)`가 불린다(서버 로그로 확인). 다만 로컬 `wrangler dev`에선 그런 소켓의 닫힘이 클라이언트까지 오지 않는 걸 봤다. 정상 클라이언트는 열리자마자 join을 보내므로 실제로는 거의 없는 경우라 더 파지 않음
- Browser pane(테스트용 내장 브라우저)의 뒤쪽 탭은 `document.hidden`이 false인데 화면 갱신은 멈춘다. 그래서 거기선 "내보내짐 → 바로 재접속"이 반복돼 보인다. 실제 브라우저의 숨은 탭은 `hidden`이 true라 재접속하지 않는다
- 정리 시간을 바꾸려면 `server/src/index.js`의 `IDLE_SEC`(또는 `wrangler.toml` `[vars]`에 `IDLE_SEC`). 게임의 ping 간격(`NET_PING` 25초)보다 충분히 길어야 한다
