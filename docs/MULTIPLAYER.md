# 멀티플레이·채팅 계획

2026-11-03 대화에서 정리한 내용. 아직 구현 전이며, 시작할 때 이 문서를 기준으로 삼는다.

## 목표

여러 사람이 같은 호숫가에 들어와 돌아다니고, 폴을 타고, 표정·이모트·채팅으로 소통한다. 처음엔 지인 테스트로 시작해 반응을 보고 키운다.

## 해야 할 일

### 클라이언트 (index.html)

1. **아바타 분리**: 지금은 캐릭터가 하나라는 전제(전역 `J`, `P`, 재질, 얼굴 텍스처, `holder`/`char`)로 짜여 있다. 캐릭터 하나를 만드는 함수(`createAvatar()` 같은 것)로 분리하고, 내 캐릭터(키 입력)와 다른 사람 캐릭터(네트워크 입력)가 같은 코드를 쓰게 한다.
2. **네트워크 층**: 입장·퇴장, 위치, 포즈, 표정, 옷, 이모트, 채팅을 주고받는다. 서버 종류를 바꿔 끼울 수 있게 인터페이스로 감싼다(Cloudflare DO → Spring 이전 대비).
3. **보간**: 다른 사람 위치는 약 100ms 늦게 보간해서 부드럽게 움직이게 한다.
4. **폴 여러 개**: **완료(2026-11-05)** 호숫가마다 각자 무대가 있는 폴 5개. 동작 버튼은 가장 가까운 빈 폴로, 폴 클릭은 그 폴로. 폴마다 잠금(`pole{i}` → `{ok, i, by}`, 다른 폴을 잡으면 앞의 건 풀림, `welcome.poles[]`), 남이 잡은 폴 위에 "사용 중". 벤치 자리 잠금은 아직.
5. **성능**: 캐릭터 하나가 메쉬 100개 이상이라 10명이면 폰이 버겁다. 형태 합치기, 멀리 있는 캐릭터 단순화(LOD), 다른 사람 얼굴 텍스처 해상도 축소.
6. **방 나누기**: 방이 꽉 차면 "호숫가 2"를 자동으로 연다. 전체 상한에 걸리면 "지금 사람이 많아요" 안내 후 혼자 모드.
7. **먼저 할 것**: 서버 없이 브라우저 안의 가짜 접속자(봇)로 여러 명을 띄워 폰에서 몇 명까지 부드럽게 그려지는지 측정 → 방 정원 확정. **완료(2026-11-04)**: `?bench`(봇을 늘리며 fps 측정), `?bots=N`

**동기화 구현(2026-11-04, index.html "multiplayer" 블록)**

- 방 고르기(2026-11-05): 입장 화면에 "1번~5번 호숫가"와 방별 인원(`GET /rooms` → `{cap, rooms:[n…]}`)을 보여 주고 고른 방으로 접속. 마지막 방은 `pole-room`에 기억(꽉 찼으면 빈 첫 방). 놀다가 설정 서랍의 "방"에서 옮김(접속만 다시). 고르는 사이 꽉 차서 `full`(4001)이면 자동으로 다른 방에 넣지 않고 "꽉 찼어요" 안내 후 혼자 모드. `?bench`일 땐 접속 안 함. 인원은 화면에 고르는 칸이 보일 때만 8초마다 새로 받음
- 주소: 개발 페이지(localhost·사설 IP)는 같은 컴퓨터의 `ws://<호스트>:8787/ws`, 배포 페이지는 `wss://polknic-ws.yujamong.com/ws`. **서버 배포·도메인 연결 전에 main에 합치면** 배포 사이트는 접속 실패 → 계속 혼자 모드(재시도만 함)
- 보내기: 위치는 0.1초마다 바뀌었을 때만(`ry`는 -π~π로 감아서). 포즈·앉기·표정·스핀·이모트는 `netState()`로 표시만 해 두고 0.1초마다 묶어서 한 번(버튼 연타로 서버 도배 제한에 안 걸리게). 폴 진입·내려오기 때 `pole`/`unpole`, 옷 바꾸면 `outfit`, 닉네임 바꾸면 `name`
- 받기: 다른 사람마다 `createAvatar(look, 0.5)` + 이름표(`.nameTag`). 위치는 지수 보간(3m 넘게 차이 나면 순간이동), 걷기 동작은 최근 0.3초 안에 위치가 바뀌었는지로, 폴 진입·착지는 포즈가 땅↔폴로 바뀔 때. 옷은 `safeLook()`으로 옷장에 있는 값만(나머지는 기본값)
- 연결 유지: 25초마다 `ping`, 10초 안에 `pong`이 없으면 끊긴 걸로 보고 재접속. 재접속은 1·2·4…30초 지수 백오프 + 지터(0.5~1.5배), 성공하면 초기화. 탭으로 돌아오거나(`visibilitychange`) 네트워크가 돌아오면(`online`) 바로 시도. 끊긴 동안 다른 사람은 사라지고 나는 계속 혼자 놀 수 있음
- HUD 상태 옆에 "같이 노는 중 N명 / 연결 중… / 혼자 노는 중"
- 확인: `.claude/launch.json`의 `server`(wrangler dev, 0.0.0.0:8787) + `static`을 띄우고 탭 두 개로 입장. `__poleDebug.net()`으로 받은 상태 확인. 폰은 `lan`으로 `http://맥IP:5174/index.html`
- 아직 없음: 폴 사용 중 표시·차단(4번), 혼자 모드 안내 문구 다듬기·인앱 브라우저 확인(6번)

### 서버 ([server/](../server/), 2026-11-04 구현)

방 관리, 메시지 중계, 폴·벤치 잠금, 검증(좌표 범위, 메시지 크기, 초당 전송 수), 닉네임·채팅 금칙어.

- 구조: Worker가 `GET /ws?room=N`(1~`MAX_ROOMS`)을 Durable Object `room-N`으로 넘김. 방 정원 `ROOM_CAP`(20)·방 개수 `MAX_ROOMS`(5)는 `wrangler.toml`의 `[vars]`
- 접속 출처는 `https://polknic.yujamong.com`과 개발용(localhost·사설 IP)만 허용, 나머지 403
- Hibernation: 접속자 정보는 소켓마다 `serializeAttachment()`(잠들면 메모리가 사라짐). `ping` → `pong`은 방을 깨우지 않는 자동 응답
- 폴 잠금: 폴이 하나라 한 명만. 소켓 attachment의 `pole` 표시로 판단(잠들었다 깨도 유지), 퇴장하면 자동 해제
- 검증: 메시지 2KB·초당 30개 초과 시 연결 끊기, 공원 밖 좌표·모르는 포즈/표정/이모트 무시, 옷은 아는 키·16자 이하 문자열만, 닉네임 12자·중복은 `#2`
- 아직 없음: 금칙어(채팅 작업 때), 운영자 강퇴, 벤치 자리 잠금
- 개발: `cd server && nvm use 24 && npm i && npx wrangler dev --port 8787 --var ROOM_CAP:3` 후 `npm test`(24개 항목 확인)
- 배포: `npx wrangler login`(본인 Cloudflare 계정으로 브라우저 로그인) → `npm run deploy`. **2026-11-04 배포**, 주소 `wss://polknic-ws.yujamong.com/ws`(`wrangler.toml`의 `routes`, DNS는 배포 때 자동 생성, workers.dev 주소는 꺼 둠)
- 지연(2026-11-04, 맥·한국 회선에서 측정): Cloudflare 무료 플랜은 한국 접속도 **LA(LAX)** 엣지로 가서 메시지 왕복이 보통 약 0.4초, 가끔 1~3초. 같이 노는 용도로는 보간으로 버틸 만하나 반응이 느리게 느껴지면 서울 서버(Lightsail 서울 + Spring) 이전을 앞당기는 근거. 폰(LTE·와이파이)에서도 재 볼 것

### DB

실시간 이동·채팅에는 필요 없다(메모리에서 중계만). 남겨야 하는 것이 생길 때만 쓴다: 신고된 채팅, 나중에 계정·저장한 옷 등. 처음엔 Cloudflare D1(SQLite) 신고 테이블 하나면 충분. 방 안의 잠금 상태 복구는 DO에 딸린 SQLite로.

## 메시지

| 메시지 | 내용 | 빈도 |
|---|---|---|
| `join` | 닉네임, 옷 설정, 표정 | 입장할 때 |
| `snapshot` | 방에 있는 모든 사람 상태 | 입장 직후 서버 → 나 |
| `move` | x, z, 바라보는 방향 | 움직일 때만 초당 4회, 서 있으면 안 보냄 |

| `outfit` | 옷 변경 | 바뀔 때만 |
| `chat` | 텍스트(최대 60자) | 1초에 1개까지 |
| `leave` | 퇴장 | 나갈 때(연결 끊김 포함) |

## 트래픽 계산 기준

- 한 명 평균 초당 약 1.5개(대부분 포즈를 잡거나 서 있음)
- 방 안 전체 = `인원 × (인원 − 1) × 1.5` (한 명이 보낸 걸 나머지 전원이 받음)
  - 6명 ≈ 45/s, 10명 ≈ 135/s, 20명 ≈ 570/s (인원 제곱으로 증가)
- 메시지 하나 ≈ 100바이트 → 10명 방 ≈ 13KB/s
- 방 정원의 실제 상한은 서버가 아니라 **폰의 그리기 성능**
  - 측정(2026-11-04, 아이폰 393×852, 크롬, 30fps 제한 상태, 전원이 화면에 보이게): 41명까지 30fps 유지, 50명 26fps. 캐릭터당 draw call 약 105. 60fps 기준 환산 약 20명
  - **방 정원 20명**으로 결정. 조건: 지인 테스트 때 오래된 아이폰·저가 안드로이드로 `?bench`를 재서 버벅이면 낮춘다(10~12명) 또는 성능 최적화(화면 밖·먼 캐릭터 계산 줄이기, 메쉬 합치기, 픽셀 비율 낮추기)를 먼저 한다. 봇 측정에는 이름표·말풍선·네트워크·발열이 빠져 있음
  - 20명 방은 방 안 메시지가 초당 약 570개(10명의 4배). DO는 들어오는 메시지만 과금이라 비용 영향은 작고, Spring 단계에선 나가는 트래픽이 10명 방의 약 2배

## 서버 선택

| | Supabase Realtime | Spring Boot WebSocket | Cloudflare Durable Objects / PartyKit |
|---|---|---|---|
| 정체 | Supabase가 운영하는 WebSocket 서버. 채널(=방)에 보낸 메시지를 그대로 전달(Broadcast), 접속자 관리(Presence) | 직접 작성·운영하는 서버 | 운영은 Cloudflare, 방마다 작은 서버 코드(JS/TS) 실행 |
| 서버 코드 | 거의 없음(브라우저 코드만) | 직접 작성 | 방 로직만 작성 |
| 게임 규칙(잠금·검증·금칙어) | 못 넣음 → DB 함수·Edge Function으로 우회 | 자연스럽게 처리 | 처리 가능 |
| 비용 | 메시지 수에 따라 증가 | 서버 1대 고정 | 무료 구간 있음 |
| 시작 속도 | 며칠 | 1~2주 | 며칠~1주 |

결정(2026-11-04 변경): **초기는 Cloudflare Workers + Durable Objects, DB는 D1.** 무료 플랜에서 돌리도록 SQLite 기반 DO + WebSocket Hibernation API 사용. DO 요금이 Lightsail 고정비를 넘으면 Spring으로 이전(주력 스택). 네트워크 층을 인터페이스로 감싸 이전 비용을 줄인다. Supabase Realtime은 받는 사람 기준 과금이라 제외.

구현 시 지킬 것:

- Worker는 입구(방 배정), 방 하나 = DO 하나(비용이 커지면 DO 하나에 방 5~10개를 담는 것 검토)
- Hibernation으로 잠들면 메모리가 사라짐 → 접속자 정보는 `serializeAttachment`/storage, 타이머는 `setTimeout` 대신 alarm
- 무료 한도 초과 시 요청이 에러로 떨어짐 → "지금 사람이 많아요" 안내 + 혼자 모드

## 채팅

- **본문은 저장하지 않는다.** 서버 메모리에서 중계만. 늦게 들어온 사람을 위해 방마다 최근 20개 정도만 메모리에 유지(재시작 시 사라져도 됨)
- **신고된 메시지만 저장**(보낸 닉네임, 시각, 내용). 저장한다면 개인정보 안내에 "신고된 메시지는 처리 목적으로 일정 기간 보관" 명시
- 표시 방식: **캐릭터 머리 위 말풍선**이 몇 초 떴다 사라짐(동숲 느낌). 화면 아래 최근 몇 줄 로그는 선택. 메뉴 숨기기 때 말풍선도 숨김
- 처음부터 넣을 악용 대응:
  - 금칙어 필터(서버에서. 브라우저만 거르면 우회됨)
  - 도배 방지: 1초 1개, 60자
  - 신고 버튼, 숨기기(차단, 내 화면에서만), 운영자 강퇴·접속 차단
  - 채팅 끄기 옵션
- 폴댄스 주제는 불쾌한 말이 몰릴 수 있어 위 대응 없이 공개 채팅을 열지 않는다

**1차 구현(2026-11-05, 브랜치 `feature/chat`)**

- 화면: HUD에 입력창(Enter로 포커스, Esc로 나감, 60자), 보낸 말은 머리 위 말풍선으로 5초. 말하는 동안엔 이름표 대신 말풍선 첫 줄에 이름(분홍 글씨, 배경 없음)이 들어가 머리 위 칸이 하나만 보임. 내 말풍선은 바로 뜨고 서버가 거절하면 지우고 이유를 토스트로 알림. "채팅 보기/숨김" 토글(`pole-chat-show`), 메뉴 숨기기 때 말풍선도 숨김. 서버에 연결됐을 때만 입력창이 보임
- 서버: [server/src/words.js](../server/src/words.js) 금칙어(글자만 남기고 비교해서 띄어쓰기·숫자 끼워 넣기도 잡음), 링크·오픈채팅 주소 차단, 1초 1개. 닉네임도 같은 금칙어 검사(입장 시 걸리면 4002로 끊고 웹은 "닉네임을 바꾸면 같이 놀 수 있어요" 후 재접속 안 함)
- 금칙어는 정상 문장을 막지 않게 좁게 잡음(섹시하다, 몸매, 벗다, 시바견, 보지 마, 한남동 등은 통과)
- **아직 없음(공개 오픈 전에 필요)**: 신고(D1 저장), 특정 사람 숨기기, 운영자 강퇴·차단. 그 전까지는 지인 테스트용
- 채팅은 멀티플레이 1단계(아바타 분리 + 실시간 연결) 이후에 붙인다

## 운영 규칙(처음부터)

- 방 정원은 위 표대로, 꽉 차면 새 방 자동 생성
- 전체 상한을 넘으면 대기 안내 + 혼자 모드(서버·비용 폭주 방지)
- 폴 잠금은 서버가 결정, 내려오거나 접속이 끊기면 자동 해제
- 닉네임: 길이·금칙어 서버 검사, 중복은 `#숫자` 붙임
- 초당 메시지 수·크기 초과 시 연결 끊기, 이동 범위 밖 좌표 무시
- 분석: GA4로 동시 접속 추이를 보며 단계 전환 시점 판단
